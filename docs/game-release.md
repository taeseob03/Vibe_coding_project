# 통합 게임 사용 안내

## 시작

서버에서 `make setup`, `make migrate`, `make dev`를 실행하고 http://127.0.0.1:8000 을 엽니다.
아이디로 접속한 뒤 닉네임·학년·학과와 캐릭터 외형을 정합니다. 처음 입력한 아이디는 계정이 생성됩니다.
아이디만으로 접속하므로 아이디를 아는 사람은 해당 계정으로 들어갈 수 있습니다.

게임 상단 `외형 설정`에서 학과 과잠·기본 캐릭터·머리 길이·머리 색을 바꾸면 계정에 저장하고 라운지에도 반영합니다.

## 게시와 변화

메인 하단 `게시`에서 글이나 사진을 올립니다. 실제 분석은 루트 .env의 Gemini 키를 사용합니다.
분석이 끝나면 현재 스탯과 표정·소품·칭호를 갱신합니다. 술은 현재 운동 스탯을 하나 차감하며 0 아래로 내려가지 않습니다.
`내 기록`에서 원본과 분석 상태를 확인하고 실패한 처리를 다시 시도할 수 있습니다.
AI 연결 없이 보려면 샘플 체험 계정/상단 체험 링크를 사용합니다. 샘플은 실제 AI 결과와 구분해 표시합니다.

## 친구와 라운지

일반 창/시크릿 창 등 쿠키가 분리된 두 브라우저로 서로 다른 아이디를 만듭니다.
라운지의 친구 초대에서 상대 닉네임을 검색합니다. 상대가 받은 초대를 수락한 뒤 같은 방을 선택하면 함께 보입니다.
라운지 좌표는 서버에서 전송하므로 두 기기에서 같은 자동 이동을 봅니다. 이름·스탯·칭호는 DB에서 불러옵니다.

## 검증

서버 단위/통합 테스트, B Python·JS 원본 테스트, 실제 Chromium의 두 계정·모바일 흐름을 검사합니다.
실제 Gemini 사진 분석도 생성한 테스트 이미지로 확인했습니다. API 키는 출력하거나 Git에 저장하지 않았습니다.
`scripts/verify_game.py`는 별도 임시 DB에서 검사하고 정리합니다. 기본은 샘플이며 `--live-ai`일 때만 실제 분석 1회를 호출합니다.
로컬 스크린샷 기본 경로는 /tmp/campus-game-preview입니다.

## 실행 범위

이 버전은 로컬 단일 서버용 게임입니다. 여러 서버 간 상태 공유·공개 운영 보안·고급 아트 자산은 선택 확장입니다.
실제 사용자 데이터가 있는 DB를 테스트용 DB로 덮어쓰지 않습니다. .env와 DB는 Git에서 제외합니다.
